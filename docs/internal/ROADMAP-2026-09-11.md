# HeliosProxy — hard-first roadmap after 1.7.0

**Date:** 2026-09-11 · **Baseline:** `main` @ `4ef4654`, release 1.7.0
**Ordering rule (per request):** the hardest items with the highest positive user
impact go first; the easiest go last.
**Inputs merged:** GitHub issues [#40]–[#55] · Sprinter `app=proxy` (2 open) · the
unfiled items in [#54] (`docs/internal/audit-2026-09/IMPROVEMENTS.md`).
**Relationship to the handover:** `HANDOVER-2026-09-11.md` remains the state of
truth for what is done and why. This file only proposes a sequence, and it
deliberately inverts the handover's "cheap first" ordering.

Scores are proposed, not measured. **Impact** = positive change for users and
operators when shipped (1–10). **Difficulty** = design + implementation +
validation + blast radius, banded XL≈9–10, L≈7–8, M≈5–6, S≈3–4, XS≈1–2.
Dependencies override the sort.

## Phase 1 — Authority and supply chain (the hard core)

This is the phase the product's name depends on. Today the daemon picks the first
reachable node whose `role = "primary"` health check passes (`select_primary_with_timeout`,
`src/server.rs`), `FailoverController`/`PrimaryTracker` are library-only, and there
is no epoch, lease or fencing anywhere. The PGConf.Brasil investigation found the
promise of transparent switchover never worked. Everything else in the HA group
is downstream of this.

| Item | Why first | Deliverable | Validated by |
|---|---|---|---|
| **H-01** [#52] | One immutable routing snapshot (cluster/shard, leader identity, authority epoch, health freshness, replica positions) consumed by startup, recovery, reads, admin, pool eviction. External Patroni/controller adapter first. | New snapshot type + provider trait + daemon wiring; conflicting primaries rejected, not first-reachable | #52 acceptance: promotion moves the write destination with no `proxy.toml` edit; old primary gets no new accepted writes; runs with and without `ha-tr` |
| **H-02** [#53] | Authority without fencing is not authority. Liveness is not permission to serve writes. | Lease expiry, fencing tokens, loss-of-quorum behavior, RPO statement per sync mode, old-primary reintegration | #53 acceptance: two partition sides cannot both authorize writes; paused processes / returning primary / witness loss / delayed messages |
| **D-01 spike** [#54] | The control-plane contract (writer epochs, shard maps, region-local snapshots) must be written before H-01's provider interface hardens. Implementation is Phase 5. | Design document + trait boundaries only; no code beyond compile-shape stubs | Review against #52/#53 interfaces |
| **Security bundle** (sprinter `18065404184e`) | `cargo deny check advisories` today: **9 errors on the default graph**; **30 with `--all-features`** — on the default graph: rustls-webpki 0.101.7 ×3 and h2 0.3.27 (both via `reqwest 0.11`), plus direct deps bincode, rustls-pemfile ×2 and anyhow, plus a dev-only crossbeam-epoch; with all features: 17 × wasmtime 26.0.1, `lru 0.12.5` (RUSTSEC-2026-0253), `paste`, `protobuf`. Every downstream consumer inherits this. | `reqwest 0.11 → 0.12`; wasmtime 26 → patched line (≥36.0.14 or ≥46/47); `lru`, `anyhow`, `bincode`, `rustls-pemfile`, `paste`, `protobuf`, `crossbeam-epoch` updates; **add `deny.toml` + a CI advisory gate** so it cannot rot | Zero advisories on all four feature profiles; `wasm_plugin_e2e` and cache/edge tests green; Lite's `cargo deny` re-run clean |
| **V-02 minimal** [#54] | H-01/H-02 acceptance cannot be claimed without a disposable primary/replica + two proxies + a committed ledger. | Minimal disposable rig first; the full failure matrix (async WAL loss, TLS rotation, rolling drain, cold cache) extends it through Phase 3 | A fault run explains itself from metrics/logs and cleans up deterministically |

**Exit criteria for Phase 1:** a real replica promotion changes the write
destination without hand-editing roles; a partitioned old primary never receives
new accepted writes; both proven with and without `ha-tr` on the V-02 rig; the
docs state plainly that a proxy-side epoch cannot fence clients that connect
around the proxy.

## Phase 2 — Correctness truth (large, user-visible)

| Item | User impact | Notes |
|---|---|---|
| **C-02** [#54] (**P0**, highest-priority unfiled) | Removes stale reads after commit/rollback; today every cache tier invalidates on write *observation*, so rolled-back writes evict and unobserved commits leave stale entries. | Open the individual issue as step 0. Stage write sets until successful commit; cover simple/extended/COPY/DDL/triggers; decide the WAL/CDC adapter or documented strict-policy bypass for direct-backend writes. Design alongside C-06. |
| **TR-07** [#49] | Makes `/api/replay` and the forensic story honest: the current journal is post-response SQL text in process memory, not a WAL. | Split into (a) truthful retention/limits + API naming, (b) transaction-boundary/parameter/outcome journal, (c) operator tooling semantics. The D-02 boundary applies: without database participation there is no atomic journal+commit, so keep `08007` honest. |
| **H-04** [#54] | Read-your-writes across failover and proxy hops; `None` must never mean "within lag threshold". | Real replay/flush/apply positions per backend capability adapter; per-session commit watermark; authenticated reconnect token. Depends on H-01's snapshot. |
| **C-06** [#54] | Security: equal SQL under `SET ROLE`, `search_path`, tenant GUC, schema change or different Bind formats must not share a result. | Couple to C-02 and C-04. |
| **C-05** [#54] | No undocumented stale success: a result's age cannot reset when promoted home→edge or L2→L1. | Strictest policy across a join; origin commit watermark + remaining freshness budget. Depends on C-02/C-03. |

## Phase 4 — Cache at scale (after correctness)

`C-01` aggregate budgets (today edge defaults allow ≈39 GiB of payload before
overhead) → `C-03` gap recovery (SSE drops/disconnected edges) → `C-04`
single-flight (the unused `pending_requests` field becomes a real coalescer) →
`C-07`→`C-09` optimizations only behind measured p99/CPU/WAN gates → `P-02`
contention measurement before any sharding work.

---

## Phase 5 — Distributed layer (optional, staged)

Implementation of `D-01` (control plane owns shard maps, writer epochs,
membership, policy versions; reads off the consensus path; fail closed when
authority expires), then `D-03` capability + shard-map contract, then `D-04`
region-aware reads. `D-02` is the durable-journal boundary already exercised by
TR-07; do not build a second one. Everything here is design-first and must keep
the honest-consistency contracts from #53.

## Suggested release trains (indicative, re-batch per gate policy)

- **1.7.1 — optional hotfix lane:** O-01 (#44), the `reqwest 0.12` half of the
  security bundle, #55, the regress-harness fixes. This is the one deviation from
  hard-first that I would actually ship.
- **1.8.0 — authority:** H-01 + H-02 + the D-01 design + the full security bundle
  + the minimal V-02 rig. Do not split H-01/H-02 across releases.
- **1.9.0 — truth:** C-02 + H-04 + C-06; TR-07 started (honest-limits half can
  land first).
- **1.10.0 — completion and proof:** H-03 + H-05 + H-06 + D-05 + V-01 + P-01 +

the exact `heliosdb-proxy` pin in `../Lite/Cargo.toml` **and** the one `version =`
line in `../Lite/Cargo.lock`.

## Definition of done (unchanged, non-negotiable)

- Full gate before any merge/release: `cargo fmt --check`; clippy `-D warnings`
  on default, `ha-tr`, `all-features`, `all-features,postgres-topology`; tests on
  the same four profiles (432 / 518 / 1726 / 1727 at 1.7.0); `cargo +1.86 check
  --locked --features msrv-features`; bench compile; `--no-default-features`
  check.
- Gate 5: every new timeout/size/limit is a `proxy.toml` key with a serde
  default, a `validate()` rule, a drift test, and entries in
  `config/proxy.full.toml` and `docs/configuration.md`.
- One heavy job at a time under the shared flock + `MemoryMax=24G`; never touch
  protected services/data; `CLAUDE.md` stays local.
- The fleet `quality-gates` theme applies: every item needs a GATE-RECORD block
  in its notes before it moves to `fixed`, and a release/merge SHA before `done`.

## Caveats in this proposal

- Advisory counts are `cargo-deny 0.19.9` as of 2026-09-11; the sprinter item was
  filed against 1.6.0 and counted 21 (downstream/Lite view), which is why this
  document quotes its own fresh numbers.
- H-03's `check_query`/`success_threshold` claims predate the current
  `health_checker.rs` and must be re-verified before scoping; the `read_strategy`
  gap is confirmed in the daemon read path.
- Impact/difficulty scores are mine, not the audit's priorities; the audit
  P0/P1/P2 labels are carried through unchanged.
- `Full`'s exposure to the exact proxy pin is unverified (no root dependency
  today); the downstream gate item must confirm it.
