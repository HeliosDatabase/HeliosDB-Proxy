### Phase 1 — C-02 remainder, the P0 (≈6 d)

The TR-07 capture already knows, per session and on both protocols, which statement
kinds ran and whether the transaction ended in COMMIT or ROLLBACK
(`journal_capture::JournalOp::{Commit, Rollback, AutoCommit}` with `StmtKind`). C-02's
missing half is exactly that signal applied to the cache:

- Feed `CacheInvalidationPlan` from the capture ops instead of a second simple-query
  parser, so extended-protocol writes stage and flush identically. Simple path keeps its
  tests; add the same schedules for Parse/Bind/Execute.
- Conservative classes: `COPY … FROM`, DDL, `CALL`/`DO`/`EXECUTE`, unknown tables →
  invalidate the whole database's entries on commit (or the tenant's), never nothing.
- L1 and L3 subscribe to the same staged set (today they rely on TTL); edge tier receives
  the commit-time invalidation via the existing registry.
- Direct-backend writes: optional `[cache] invalidation_source = "logical"` adapter that
  consumes a logical replication slot (`pgoutput`, `publication` per tenant) and maps
  relation OIDs → table names; behind `postgres-topology`-style feature, off by default.
  This is the only piece that needs new backend credentials; ship it as a second slice.
- Acceptance: the two-client read/refill/commit schedule and the direct-write schedule
  as integration tests under a strict policy; differential run against uncached PG.

### Phase 2 — HA contract completion (≈14 d, can interleave two sessions)

- **H-01 remainder** (#52): Patroni adapter (`GET /cluster` on the REST API, leader +
  timeline + `pending_restart`); reject conflicting primaries (two nodes reporting
  `pg_is_in_recovery() = false` with different timelines → no leader, fail closed, alert);
  one immutable `RoutingSnapshot` consumed by reads, pool eviction and admin, replacing
  the configured-roles read path.
- **H-02 remainder** (#53): consume the provider's lease/fencing token (Patroni leader
  key TTL, or DCS epoch) so the proxy epoch is derived, not self-declared; document that
  fencing is the database's/controller's job; partition validation deferred to Phase 3.
- **H-05 remainder** (`31fae26a2e17`): enforce `TenantConfig.max_connections` at accept;
  per-node active+idle backend caps; fair backend acquisition queue with max wait and
  jittered retry per destination; reserved health/admin capacity; queue depth, wait
  histogram, per-tenant rejections in Prometheus. Gate with P-01 at the recorded client
  counts (1/16/64), plus the failover reconnect-wave measurement.
- **H-04 remainder**: per-session commit watermark seeded from the journal's
  `commit_seq`/backend LSN at COMMIT; `require_known_lag` already strict; authenticated
  reconnect token deferred to D-01/D-02 design.
- **H-03 residual** (inflight accounting, P2C hysteresis) folds into H-05's per-node caps.

### Phase 3 — V-02 laboratory (≈5 d) — pulled forward

Three open acceptances (H-02 partition cases, C-03 warm/gap drill, TR-08 mid-transaction
loss) and this week's backend incident all say the same thing: the shared host backend is
not a lab. Build `tests/lab/` as a disposable compose stack: primary + 2 replicas
(Patroni or `pg_promote` scripting), two proxies, a ledger client that records committed
transfers and client-visible results, chaos verbs (pause, kill, partition via `tc`/iptables
inside the network namespace, WAL delay), bounded runtime and deterministic teardown, run
only under the fleet lock with the bounded scope. Publish the supported-guarantees table
and the unmet cases. Reuse `test_tr07_committed_history_replay_reproduces_the_ledger` as
the first ledger check.

### Phase 4 — cache trust (≈12 d)

- **C-06 identity** first: extend `CacheKey` with effective role, `search_path`, tenant
  GUC generation, schema version and Bind result formats; bypass when identity cannot be
  captured. **C-04 single-flight** couples to it (leader per identity + freshness,
  bounded waiters, generation validation, follower cancellation semantics).
- **C-05 freshness SLA**: per-table policy (`primary`/`bounded_staleness`/`eventual`) in
  `[cache]`, origin commit watermark carried across tiers (uses H-04 lag + TR-07 commit
  seq); an aged sample or missed event causes wait/bypass/fail, never stale success.
- **C-03 close**: live drill in the Phase 3 lab; then `752317ee59d4` → done.

### Phase 5 — availability and policy parity (≈15 d)

- **H-06 remainder** (`597f3caab4ef`): shared request executor applying rate limit,
  circuit breaker, rewrite rules and tenant identity to HTTP/GraphQL/MCP; per-request
  identity; configurable gateway timeout/concurrency; MCP read-only as a role.
- **TR-08** (#50): retain acknowledged named statements/portals with Bind bytes per
  session (the journal's byte-faithful `JournalValue` path already exists), re-establish
  on the replacement backend, keep TR-01's no-second-dispatch proof; lab acceptance.
- **TR-09** (#51): `[replay] buffer_small_reads_bytes` opt-in, measured with P-01
  first-row latency and RSS.
- **P-03 remainder**: histograms (detection/reconnect/restore/replay/queue), replay
  refusal reasons, cache gap/coalescer/retained bytes.
- **P-02**: contention study at 1/16/64 before any lock restructuring.

### Phase 6 — distributed layer and cache extras (design first)

D-02 is now partly real (the journal has stable commit seq, source identity, lifecycle
outcomes, segmented CRC logs); what remains is the design doc for cross-proxy
continuation and the honest boundary already stated in `transaction-replay.md`. D-01
(control plane snapshot contract), D-03 (capability manifest per backend, shard map),
D-04 (placement) follow as design + staged slices after Phase 2's `RoutingSnapshot`
exists. C-07/C-08/C-09 after C-02/C-06 land.
