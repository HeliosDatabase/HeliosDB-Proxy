# TR-05 implementation — partial extended-batch delivery

An extended batch may contain several complete Execute frames before `write_all`
fails. A timeout also does not prove that the backend received no bytes. The daemon
now reports OutcomeUnknown for all extended-batch write errors, timeouts and
WriteZero errors. Its existing replay decision table then refuses possibly committed
work using TR-01's whole-batch classification.

This is intentionally conservative even when a transport fails on its first write;
it does not depend on buffering details of TCP or TLS. Pre-dispatch connect/idle
failures keep their NotDelivered classification. A held Parse is sent separately;
a failure there precedes dispatch of the Execute batch and remains NotDelivered.

No new configuration threshold is introduced. The helper uses the existing
`[limits] backend_write_timeout_secs` value. Healthy writes still use the same
`timeout(write_all(...))` operation.

The deterministic unit test `tr_partial_extended_writes_never_authorize_commit_reexecution`
uses a writer that accepts an exact prefix, then errors. It checks every byte offset
of a BEGIN/INSERT/COMMIT/Sync batch, including all frontend frame boundaries, both
initially-autocommit and already-in-transaction client states. It verifies the bytes
accepted and rejects reexecution in the real decision table. Additional cases stall
after COMMIT Execute, return a zero-length write, complete successfully, and exercise
a pre-dispatch connection-failure decision. The real-PG TR-01 fixture separately
checks the ledger after COMMIT succeeds but its response is lost.

The frozen candidate passed the five test profiles (default, ha-tr, all-features,
all-features/postgres-topology, no-default), four required clippy profiles and the
Rust 1.86 MSRV check. All seven real PostgreSQL outcome cases passed. The full
benchmark comparison completed, but individual regressions require investigation
before final acceptance. Aggregate medians are nearly flat; that does not establish
a per-path performance pass.
TR-01's cross-cycle identity follow-up and TR-02/03/04 remain
open; this delivery fix does not imply general replay safety or HA promotion.
