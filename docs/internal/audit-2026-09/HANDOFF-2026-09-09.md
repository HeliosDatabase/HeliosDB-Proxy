DIRECTION OF THE SOLUTION
1. Make Transaction Replay trustworthy first. Next central fix is an acknowledged, versioned statement/portal registry, with immutable Parse dependencies in replay history. The routing registry is updated before PostgreSQL acknowledges Parse and cannot safely supply recovery generations. Then add explicit replay eligibility/backend capabilities, transactional GUC/savepoint restoration, observation verification and one recovery deadline. Keep unknown commit outcomes unknown; do not promise exactly-once without database participation.
2. Reinforce the daemon's HA foundation: one authoritative topology snapshot with epochs, quorum/lease authority and enforceable fencing; actual configured health/routing strategies; causal replica positions; bounded, fair connection/recovery admission. These must work independently of ha-tr.
3. Make caches correct before optimizing: aggregate byte/tenant budgets, commit-aware invalidation, gap/epoch recovery, full security/session identity, bounded single-flight and measurable freshness. Fine-grained invalidation, compression and warming follow that foundation. Sonnet's O(1) LRU and authoritative-home-clock suggestions partly already existed; the backlog records the actual gaps.
4. Build the upper distributed layer as separate authority, outcome-journal and cache contracts. Reuse Lite/Full components selectively. Durable replay requires atomic backend outcome/idempotency participation; a proxy journal alone cannot establish exactly-once. Versioned shard maps, backend capabilities, causal reconnect tokens, regional placement and bounded cross-shard fan-out prepare global PG-wire deployments without coupling them to ha-tr. Demonstrate the advantage over HAProxy+Patroni with reachable fault/HA/latency tests rather than feature claims.
