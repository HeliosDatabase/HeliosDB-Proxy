# HeliosProxy 3.0.0

*2026-11-18 · `heliosdb-proxy` 3.0.0 on [crates.io](https://crates.io/crates/heliosdb-proxy) ·
prebuilt binaries and checksums on this GitHub release · image
`ghcr.io/heliosdatabase/hdb-heliosdb-proxy:3.0.0`*

HeliosProxy 3.0.0 closes the gap between the simple and the extended query protocol:
plugins, rewrite rules, the tenant row filter and the query cache now see prepared
statements the way they see simple queries. It shuts down gracefully, ships WASM plugins
as signed artefacts that reload without a restart, and gives AI agents identities, a
result cache and memory on the MCP gateway.

The full list of changes is in
[CHANGELOG.md](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/CHANGELOG.md#300---2026-11-18).
These notes are organised for an upgrade from 2.2.

---

## Why 3.0.0

- **The Rust library API breaks.** Many public configuration and metrics structs gain
  fields, so struct literals no longer compile, and a few signatures change. If you only
  run the `heliosdb-proxy` binary, this does not affect you.
- **Several defaults and behaviours change** in ways an existing deployment can notice:
  the result caches cache much less unless you vouch for your backend, prepared
  statements now pass your plugins and tenant filter, unidentified tenants are refused,
  and more. Each is listed in [Upgrading from 2.2](#upgrading-from-22).
- **What stays compatible:** the daemon's command-line flags, the PostgreSQL wire
  protocol, the admin HTTP API (endpoints are only added) and the `proxy.toml` format. A
  2.2 configuration file loads unchanged, unless its `[schema_routing] analytics_node`
  names no configured node.

## Highlights

### Statement hooks on the extended protocol

The pre-query and route plugin hooks, the `[query_rewrite]` rules and the
`[multi_tenancy]` row filter (with `unknown_tenant`) used to read simple queries only.
Most drivers and ORMs send every statement as `Parse`/`Bind`/`Execute`, so those
statements passed untouched. Now every `Parse` passes them before the proxy records
anything of it: a rewrite replaces the SQL the proxy prepares, routes, caches and
journals, and a refusal refuses the whole cycle before any backend sees it. A later
`Bind` of a prepared statement runs the plugin hooks again, so a plugin that limits
executions sees each one. `[schema_routing]`, the route plugin's node and branch answers,
the post-query hook and a plugin's `cached` answer cover extended cycles too.

Nothing to enable: this applies wherever `[plugins]`, `[query_rewrite]` or
`[multi_tenancy] tenant_tables` is configured. Statement text that is not valid UTF-8 is
refused with `22021` while any of them is active (use `client_encoding` UTF8).
Details: "Statement hooks on the extended protocol" in
[docs/configuration.md](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#statement-hooks-on-the-extended-protocol).

### Graceful shutdown on SIGTERM and SIGINT

`docker stop`, a Kubernetes pod termination and `systemctl stop` used to end every
session at once. Now SIGTERM or SIGINT closes the PG-wire listener and the HTTP, MCP and
GraphQL gateway listeners, `/health/ready` (`/readyz`) answers 503 `Proxy is draining`,
and each session ends with FATAL `57P01` as soon as nothing of it is in flight: idle
sessions at once, others when their transaction, extended cycle or `COPY` is over.
Accepted gateway requests are answered and the recovery journal is flushed. The process
exits 0 when the last session is gone, or at `shutdown_drain_timeout_secs`; a second
signal exits at once. The SIGUSR2 binary handoff drains the same way.

```toml
shutdown_drain_timeout_secs = 60   # default; env override HELIOS_DRAIN_TIMEOUT_SECS
```

Give your supervisor at least that long before it sends SIGKILL: `docker stop -t 70`
(or `stop_grace_period: 70s` in Compose; Docker's default is 10 s),
`terminationGracePeriodSeconds: 70` in Kubernetes (default 30), `TimeoutStopSec=70` in
systemd. Or lower the drain timeout. New counters: `sessions_drained` /
`heliosdb_proxy_sessions_drained_total`, and `draining` in `GET /metrics`.

### Signed plugin artefacts, hot reload and the `helios-plugin` CLI

Plugins are distributed as `.tar.gz` artefacts (`manifest.json`, `plugin.wasm`,
`plugin.sig`, `manifest.sig`). The plugin directory is the source of truth: it is
reconciled at startup, on SIGHUP, on `POST /plugins/reload` and, with `hot_reload`,
continuously. A new version replaces the running one only once it has loaded, so a bad
upload leaves the old version serving; a removed file unloads its plugin. A plugin that
could never run (unknown hook, missing export, wrong ABI signature) is refused at load
with the reason in the log and in `GET /plugins/files`. Each call's memory is now
limited by `memory_limit_mb`.

```toml
[plugins]
enabled = true
plugin_dir = "/etc/heliosproxy/plugins"
trust_root = "/etc/heliosproxy/plugin-keys"   # dir of *.pub, one key file, or 64 hex digits
hot_reload = true                 # default false
hot_reload_interval_ms = 1000     # default
hot_reload_debounce_ms = 500      # default
max_artefact_bytes = 67108864     # default, 64 MiB
require_signed_manifest = false   # default; true = only artefacts with a verifying manifest.sig
```

```bash
helios-plugin keygen --out-dir keys --name release          # keys/release.key, keys/release.pub
helios-plugin pack --wasm guard.wasm --manifest plugin.yaml \
  --sign-with keys/release.key --output guard.tar.gz
helios-plugin inspect guard.tar.gz
helios-plugin verify guard.tar.gz --trust-root keys --require-signed-manifest
cp guard.tar.gz /etc/heliosproxy/plugins/ && cp keys/release.pub /etc/heliosproxy/plugin-keys/
```

`helios-plugin new <name>` scaffolds a plugin crate that builds and loads, and
`helios-plugin install` installs working artefacts from a registry. Hooks now receive
the session's identity, database, branch, tenant, client address and `helios.*`
settings in `hook_context`, so the first-party plugins that decide by tenant, role,
region or agent work as documented, and their Block and Rewrite answers now take effect.
See [WASM Plugins](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#wasm-plugins-plugins).

### Branch routing

A `/*helios:branch=<name>*/` routing hint or a route plugin's `branch` answer moves the
session to a branch database before the statement runs, and the session stays there
(`branch=` with no name moves it back). A move happens only at a request boundary
outside a transaction (`25001`), when the session holds no backend-only state (`0A000`),
and when `[[hba]]` admits the new database (`28000`). Counted in
`heliosdb_proxy_branch_moves_total`.

```toml
[branch]
route_enabled = true        # default false: a branch request is refused (42000)
route_mode = "database"     # default; "nano" = <base>@<name> on HeliosDB-Nano
route_allow = ["staging"]   # default [] = any valid name
```

### Query cache: extended protocol, settings proof, tiers, compression, refresh-ahead, heatmap

- **Extended-protocol reads** (`[cache] extended_protocol = true`, default): an unnamed
  `Parse`/`Bind`/`Execute`/`Sync` cycle and the execution of a named prepared statement
  are answered from cache, keyed by text, parameter types, values, formats and result
  formats.
- **Settings proof, reused per connection.** Every cached read is keyed by the startup
  parameters and the backend's effective settings (`SHOW ALL`). The proof is kept on the
  backend connection for `[cache] proof_ttl_ms` (default 1000, at most 300000; `0` =
  prove before every read) and is retired by any other statement on that connection or a
  reported parameter change. Under transaction and statement pooling it is parked with
  the connection.
- **Tier sizes and L2 compression:** `l1_max_entries = 500`, `l1_max_bytes = 33554432`
  (per connection), `l2_max_bytes = 268435456`, `l2_compression = "none" | "lz4" | "zstd"`
  (default `"none"`), `l2_compression_min_bytes = 4096`, `l2_zstd_level = 3`, and
  `l2_evict_headroom_pct = 5` (how much more of `l2_max_bytes` one eviction pass frees).
- **Refresh-ahead:** `refresh_ahead_ratio` (default `0.0` = off) lets one read refill a
  hot entry before it expires while others are still served it;
  `refresh_ahead_claim_timeout_ms = 5000`.
- **Heatmap:** `heatmap_enabled = true` records per-table hits, misses, stores and
  invalidations; `GET /api/cache/heatmap` lists the hottest tables with recommendations.
- **`extra_volatile_functions`** lists your volatile functions so no cache serves them.

```toml
[cache]
enabled = true
trust_backend_read_effects = true   # required to cache anything but SELECT <integer>; read the contract
proof_ttl_ms = 1000
l2_compression = "lz4"
```

Read the `trust_backend_read_effects` contract in
[Query Cache](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#query-cache-cache)
before setting it: it vouches that skipping a read's backend execution hides no side
effect and that its result depends only on the proven settings and the tables it names.

### MCP gateway: principals, tool-result cache, agent memory

- **`[[mcp.principals]]`** binds a bearer token to an agent identity (`id`, `token`);
  `[mcp] auth_token` keeps working as the principal `default`.
- **Tool-result cache** (`tool_cache_enabled = false` by default; needs the
  `query-cache` feature and `[mcp] trust_backend_read_effects = true`): repeated
  `query` / `list_tables` calls are answered per principal and tenant, retired by every
  write through the proxy and by `tool_cache_ttl_secs = 60`. Inspect and clear with
  `GET /api/mcp/cache` and `POST /api/mcp/cache/clear`.
- **Agent memory tools** (`memory_enabled = false` by default; needs a principal and a
  PostgreSQL MCP backend): `memory_put`, `memory_get`, `memory_list`, `memory_search`,
  `memory_delete`, stored in `memory_table` (default `heliosdb_mcp_memory`) owned by
  principal and tenant, with TTLs and quotas.
- **Result caps:** `max_result_rows = 10000`, `max_result_bytes = 16777216`; larger
  results are truncated and marked `truncated`.

```toml
[mcp]
enabled = true
tool_cache_enabled = true
trust_backend_read_effects = true
memory_enabled = true
memory_backend_user = "helios_memory"

[[mcp.principals]]
id = "etl-agent"
token = "${MCP_ETL_TOKEN}"
```

See [MCP Agent Gateway](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#mcp-agent-gateway-mcp-and-agent-contracts-agent_contracts)
for every key and the memory table DDL.

### `GET /api/stats` for pollers

One versioned JSON document (`schema_version` 1) with nodes, pools, sessions, traffic,
cache, tenants, rate limit, transaction replay and gateways. Every section is always
present (`{"enabled": false, "reason": ...}` when off); within version 1 fields are only
added. Lists are cut at `[admin] stats_max_items` (default 1000). Field reference:
[docs/admin-api.md](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/admin-api.md#get-apistats--schema_version-1).

### Pooling, rate limiting, circuit breaker and tenants that behave as configured

- **Statement pooling** (`[pool_mode] mode = "statement"`) now refuses a lone `BEGIN`
  (`0A000`) and ends a session that leaves a transaction block open, as PgBouncer's
  statement mode does.
- **`[rate_limit]`** enforces `default_qps` above 1 000 (a hidden 60 000-per-minute
  window capped it), enforces `max_concurrent` (`53400`), and drops idle buckets every
  `cleanup_interval_secs` (default 60). The sliding window is opt-in:
  `window_max_requests` (default 0 = off), `window_secs` (default 60).
- **`[circuit_breaker]`** recovers: after `open_secs` a request is admitted as a
  half-open probe and `success_threshold` successes close the circuit. It used to stay
  open until restart.
- **Tenants:** per-tenant active-query caps cover the HTTP, MCP and GraphQL gateways;
  a SIGHUP resizes per-tenant caps and budgets; new `max_journal_bytes_per_tenant`;
  credential-stuffing detection (`[anomaly]`) now receives authentication events
  (`max_auth_windows = 10000`).
- **COPY:** optional `[limits] copy_idle_timeout_secs` (default 0 = off) ends a stalled
  `COPY FROM STDIN` with `57014`.

## Upgrading from 2.2

Work through this list before rolling 3.0.0 out. Items marked *library* matter only if
you link `heliosdb-proxy` as a Rust crate.

**Behaviour of the daemon**

- [ ] **Result caches cache only literal scalar reads by default.** *Who:* deployments
  with `[cache] enabled = true` or `[edge]` caching. Without
  `[cache] trust_backend_read_effects = true` only `SELECT <integer literal>` is cached;
  everything else runs on the backend. A session that writes, runs `SET`, `SET ROLE` or
  any statement that may change its execution context stops using the cache. *Do:* read
  the contract in [Query Cache](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#query-cache-cache)
  and set `trust_backend_read_effects = true` if your backend meets it; watch
  `heliosdb_proxy_cache_hits_total`.
- [ ] **Cached reads prove the backend's settings**, reusing the proof per connection for
  `[cache] proof_ttl_ms` (default 1000). A backend configuration reload reaches cached
  reads within that time. *Do:* nothing; `proof_ttl_ms = 0` proves before every read.
- [ ] **Prepared statements pass plugins, rewrite rules and the tenant filter.** *Who:*
  `[plugins]`, `[query_rewrite]` or `[multi_tenancy] tenant_tables`. Statements that
  used to run as sent may now be blocked (`42000`), rewritten, filtered or refused
  (`42501`). *Do:* test your driver's traffic against your rules.
- [ ] **Non-UTF-8 statement text is refused (`22021`)** while a plugin hook, rewrite
  rules or the tenant filter is configured. *Do:* use `client_encoding` UTF8.
- [ ] **Unidentified tenants are refused.** *Who:* `[multi_tenancy]` with
  `tenant_tables`. New key `unknown_tenant`, default `"refuse"`: a session naming no
  configured tenant gets `42501` on a statement that references a tenant table. *Do:*
  set `unknown_tenant = "passthrough"` to keep 2.2 behaviour. With
  `identify_by = "database"`, a session without a `database` parameter now uses its user
  name, as PostgreSQL does.
- [ ] **The row filter refuses what it cannot rewrite.** `WITH`, parenthesised queries,
  `TABLE t`, `VALUES`, several statements, a tenant table in a subquery or with an alias,
  `INSERT` other than `INSERT INTO t (cols) VALUES (...)`, `ON CONFLICT ... DO UPDATE`,
  an `UPDATE` of the tenant column, `DO`, `CALL` and the functions in the new
  `refused_functions` key are refused with `42501`. *Do:* rewrite such statements, or
  rely on PostgreSQL row-level security for them.
- [ ] **`[[hba]]` rules and tenant identity read `<db>@<branch>` as `<db>`.** A rule
  without `@` now also covers its branches. *Do:* review reject rules if you use
  HeliosDB-Nano branches.
- [ ] **Routing targets must be configured nodes.** A `node=` hint or a route plugin
  answer naming no `[[nodes]]` entry is refused with `42704`; an unknown
  `[schema_routing] analytics_node` is a startup error. *Do:* list every target in
  `[[nodes]]`.
- [ ] **A branch request without `[branch] route_enabled` is refused (`42000`)** instead
  of running on the session's own database. *Do:* enable branch routing, or remove the
  hint.
- [ ] **Plugin loading is stricter.** A manifest hook the module does not export, a hook
  the proxy never calls, symlinked files, `enable_threads = true` and an on-disk
  `cache_dir` are refused; `.tar.gz` artefacts in `plugin_dir` are now loaded; without
  `trust_root` signatures are not checked and startup warns. *Do:* check
  `GET /plugins/files` after the upgrade; set `trust_root` in production.
- [ ] **SIGTERM and SIGINT drain instead of killing the process.** *Do:* raise your
  supervisor's grace period to at least `shutdown_drain_timeout_secs` (60 s by default),
  or lower that key.
- [ ] **Sessions holding backend-only state end on a lost backend.** A session with
  temporary tables, `WITH HOLD` cursors, SQL `PREPARE`d statements, `LISTEN` or
  session-level advisory locks gets `08006` at a failover instead of continuing without
  them; under `tr_mode = none` such an idle session gets `57P01`. *Do:* make clients
  reconnect and recreate that state.
- [ ] **Builtin function names no longer make a read retry- or offload-safe.** *Who:*
  `tr_mode = "select"` or `"transaction"`, and standby read offload. *Do:* list
  functions you trust in `tr_read_functions`.
- [ ] **Statement pooling is enforced** (`0A000` for a lone `BEGIN`; a block left open
  ends the session). *Do:* use transaction pooling for clients that hold transactions.
- [ ] **`[rate_limit]` changes.** `default_qps` above 1 000 is now enforced as written
  (it was capped near 1 000 after the first minute); `max_concurrent` above 0 is now
  enforced (`53400`). *Do:* re-check both values; use `window_max_requests` /
  `window_secs` if you relied on a per-window cap.
- [ ] **Legacy `FunctionCall` messages are checked.** New key `function_call`, default
  `"large-objects"`: the built-in large-object functions are forwarded (libpq `lo_*`,
  JDBC `LargeObject`, `pg_dump`), every other function is refused with `0A000`. *Do:* set
  `function_call = "any"` if a client calls other functions by OID.
- [ ] **New connections wait for a healthy node** up to `[limits] startup_node_wait_ms`
  (default 5000) during an outage instead of failing at once. *Do:* set it to `0` for
  the immediate `08006`.
- [ ] **Gateway results are capped.** HTTP `/sql` refuses results over
  `[http_gateway] max_result_rows` (10000) or `max_result_bytes` (16 MiB) with HTTP 413,
  GraphQL with `RESULT_TOO_LARGE`; MCP tools truncate them. *Do:* raise the keys (up to
  1000000 rows and 1 GiB) for large results.
- [ ] **The `cache_refresh` hint is active.** `/*helios:cache_refresh*/` (also
  `refresh`, `nocache_read`, `cache=refresh|force|update`) now sends the read to the
  backend and refreshes the entry. *Do:* remove the hint where it was left in.
- [ ] **Routing hints inside string literals, dollar quotes or quoted identifiers are no
  longer read or stripped.** *Do:* nothing, unless you relied on that.
- [ ] **A malformed simple `Query` ends the session with FATAL `08P01`.**
- [ ] **Release binaries include `postgres-topology`.** `[topology] provider =
  "postgres"` and `"patroni"` now work with the prebuilt binaries, as with the Docker
  image.

**Library API (*library*)**

- [ ] **Struct literals.** These gain public fields: `CacheToml`, `CacheConfig`,
  `L2Config` (and `size_mb` is replaced by `max_bytes`), `L2Entry` (`raw_len`),
  `PluginToml`, `PluginRuntimeConfig`, `BranchConfig`, `McpConfig`,
  `MultiTenancyToml`, `LimitsToml`, `AnomalyToml`, `AnomalyConfig`, `RateLimitToml`,
  `RateLimitConfig`, `HttpGatewayConfig`, `GraphqlGatewayConfig`, `ProxyConfig`,
  `ServerMetricsSnapshot`, `TenantBudgetStats`, `VerifyReport`, `AdminState`. *Do:* add
  `..Default::default()` to struct literals (or set the new fields).
- [ ] **`GatewayPolicy::tenant_sql`** returns `Result<Cow<str>, PolicyDenied>`; a refused
  statement is `Err(PolicyDenied::TenantStatement)`. *Do:* handle the `Err` (HTTP 403).
- [ ] **`PolicyDenied`** gains `TenantStatement` and `TenantQueryLimit`. *Do:* extend
  exhaustive matches.
- [ ] **`GatewayPolicy::check_node`** returns `Result<NodeAdmission, PolicyDenied>`.
  *Do:* keep the `NodeAdmission` alive for the request (it holds a half-open circuit's
  probe).
- [ ] **`routing::HintParser::strip`** returns `Cow<'_, str>`. *Do:* call
  `.into_owned()` where a `String` is needed.
- [ ] **`L1HotCache::put`, `L2WarmCache::{put_evicting, shed, shed_paced}`** return the
  number of entries evicted or removed; **`plugins::HotReloader::watch_dir`** returns
  `PathBuf`.
- [ ] **New public items** you may use: `plugin_artefact`, `mcp_memory`, `mcp_cache`,
  `database_name`, `gateway_drain`, `pool::{SettingsProof, ParkedSettings, PooledConn}`,
  `cache::{TableGenerations, GatewayWrites, WriteScope, codec}`.
- [ ] **Library modules no longer simulate success.** Modules the daemon does not call
  used to return made-up values, or report success for work that never happened, when
  they had no backend to talk to. In 3.0.0 they do the work on a connection you give them
  or return an explicit error:
  - OAuth introspection and token exchange, JWKS fetching, and the Vault and AWS Secrets
    Manager credential providers return `NotSupported`; nothing fabricated is cached.
  - `FailoverController` without a backend template fails a failover (and records it as
    failed) instead of reporting one that promoted nothing.
  - `CursorRestore::restore_cursor` and `SessionMigrate::migrate_session` take the
    session's `&mut BackendClient` and recreate the cursor or the session state on it.
  - `ConnectionPool`, `ConnectionPoolManager` and `HealthChecker` without a backend
    template refuse to hand out connections or to report nodes healthy.
  - `SchemaDiscovery` against a backend, and `GraphQLEngine` without a backend, return
    errors instead of mock tables or empty data.
  - `rewriter` conditions and `RewriterConfig` fields that were never evaluated are
    removed; `distribcache` reports replication and invalidation failures per peer.

  *Do:* attach the backend template or connection these APIs now require, and handle the
  new errors. The full list, with every removed item, is in the CHANGELOG under
  "Library API (breaking)".

## Security fixes

- Plugins, rewrite rules and the tenant row filter now apply to statements sent over the
  extended protocol (they were bypassed by prepared statements).
- The first-party plugins' Block and Rewrite answers now take effect (they were
  silently ignored), and a plugin answer the proxy does not understand is a failed hook
  call instead of a pass.
- A plugin's memory limit is enforced; plugin signatures can bind the manifest
  (`manifest.sig`, `require_signed_manifest`); artefacts must contain exactly the allowed
  entries within `max_artefact_bytes`; plugin files are not followed through symlinks.
- A routing hint or plugin can no longer make the proxy dial an arbitrary `host:port`
  with proxy-held credentials: targets must be configured nodes.
- Row-level tenant filter: a `WHERE a OR b` condition no longer leaks or deletes other
  tenants' rows, a `--` comment can no longer comment the filter out, and the
  `INSERT`, `UPDATE`, Unicode-escape, alias and dynamic-SQL bypasses are closed.
- `<db>@<branch>` database names no longer escape `[[hba]]` reject rules or tenant
  identity.
- Routing hints are read only from comments, never from inside literals.
- Volatile and session-state reads (`current_user`, `current_setting`, `txid_current`,
  `'now'`, ...) are never served from a cache; `EXPLAIN ANALYZE` writes and writes
  through the HTTP, MCP and GraphQL gateways invalidate cached reads.
- Gateway results are bounded in memory, including a single oversized row.
- Legacy `FunctionCall` messages no longer bypass tenant admission, the rate limiter,
  the circuit breaker and cache invalidation.

## Performance

Figures are from the project's evidence host (PostgreSQL 18.4 on the same host), with
the conditions stated; they are not general claims.

- **Cache settings proof.** pgbench's select-only script, 16 clients, session pooling,
  `[cache] enabled` with `trust_backend_read_effects = true`: proving the settings before
  every read gave about 4 200 reads per second over the simple protocol (68 000 for a
  build without the proof, 66 000 with `backend_context_immutable = true`). Over the
  prepared protocol, 4 400 per second with the per-read proof against 84 000 with the
  proof reused per connection (81 000 with the cache bypassed). `proof_ttl_ms` (default
  1000) is the per-connection reuse that 3.0.0 makes the default.
- **Full L2 eviction.** A full L2 used to rescan its map once per evicted entry, stalling
  one session for 20 s to 23 min after a read-heavy run with a few hundred thousand
  entries (64 clients). One pass now scans once and frees `l2_evict_headroom_pct`
  headroom.
- **Smaller wins, no behaviour change:** the recovery journal's size cap no longer
  re-walks the transaction per statement (it was quadratic); routing-hint parsing is back
  to its earlier cost after the literal-safe rewrite; the semantic tier's slot is back to
  216 bytes (a full-tier store had become 6 % slower, 21 % with eight threads); the
  futures awaited per cached read are 40-56 bytes again (an L1 hit had become 13 %
  slower).

## Fixed

**Failover and transaction replay**
- Sessions holding state only the failed backend had end with `08006` instead of
  continuing without it; refused statements are no longer recorded or replayed.
- `SELECT set_config(name, value, false)` counts as session state.

**Pooling, routing and admission**
- Statement pooling behaves as statement pooling; pool-mode transaction detection reads
  keywords (`START\tTRANSACTION`, `ROLLBACK\nTO sp`, `... AND CHAIN`).
- An unnamed `Parse` later in a batch no longer leaves a stale `optimize_unnamed_parse`
  record.
- Extended-protocol `pg_advisory_unlock_all()` and `DISCARD ALL` release a tenant's
  active-query permit; `COMMIT PREPARED` / `ROLLBACK PREPARED` in drivers' shapes pass a
  saturated tenant cap.
- An open circuit recovers after `open_secs`.
- Node, pool and reconnect caps above Tokio's semaphore limit are refused at
  validation instead of panicking.

**Caches**
- A full L2 no longer stalls a session; the L1 byte account no longer leaks after an
  entry-bound eviction; compressed L2 payloads no longer pin worst-case buffers.
- Cache-tier restrictions (`L1`/`L2` hints) are honoured across lookup, promotion and
  store; the HTTP gateway's cache follows the relay's rules.
- Edge reconnect cursors resume at the last applied invalidation.

**Plugins and the CLI**
- PKCS#8 v2 Ed25519 keys are accepted; a plugin waiting for a `max_plugins` slot loads
  in the rescan that frees one; `enable_simd = false` disables SIMD; `cache_modules`
  keeps modules by content hash.
- `helios-plugin install` installs working plugins; `helios-plugin new` scaffolds a
  plugin that builds and loads.

**Gateways and observability**
- MCP, HTTP `/sql` and GraphQL results are capped; gateway writes retire cached reads.
- The anomaly detector's credential-stuffing detection receives authentication events.

## Not in 3.0.0 (planned)

Some capabilities that earlier material announced are **not part of 3.0.0**. They are
planned for later 3.x minor releases:

- Client authentication beyond passthrough and SCRAM: JWT, OAuth 2.0, API keys and LDAP
  (the modules exist as a library API but cannot be selected in `proxy.toml`).
- Per-tenant connection pools and schema isolation for tenants.
- Some `[pool]` / `[pool_mode]` keys that are parsed but have no effect yet.
- Switchover buffering of client queries and coalescing of single-row `INSERT`s.
- Rate limiting keyed by tenant or by query cost, an adaptive circuit breaker, and
  analytics endpoints for N+1 detection, query intent and slow queries.
- Schema-routing table discovery, and GraphQL schema introspection and result caching.
- Resolving the cache dependencies of views, functions and row-level security policies
  to their base tables. Until then, declare them with the `cache_tables` hint (see
  [Cache hints](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#cache-hints)).
- Single-flight on cold cache misses (refresh-ahead covers entries that already exist).
- GraphQL mutations on tables whose key column is not named `id`: the gateway addresses
  rows by `id`, so an update or delete on another table fails at the backend.

Longer term, with no version promised: a native HeliosDB topology provider for the
standalone daemon, a zero-downtime upgrade orchestrator, session migration, cursor
restore, a failover controller that promotes databases, and a distributed peer-to-peer
cache.

## Compatibility

- **Rust:** MSRV 1.86 (`rust-version` in `Cargo.toml`).
- **Backends:** PostgreSQL and any PostgreSQL-wire backend (HeliosDB-Nano, HeliosDB-Lite,
  HeliosDB-Full, Aurora/RDS and others). The MCP agent memory tools need a PostgreSQL MCP
  backend.
- **Feature flags:** no flag was added or removed. `query-cache` and `distribcache` now
  pull `zstd` and `lz4_flex`, which a build without either no longer compiles.
  `postgres-topology` is still separate from `all-features`.
- **Release binaries** (Linux x86_64 and aarch64, macOS x86_64 and aarch64) and the
  Docker image are built with `all-features,postgres-topology`.
- **Admin API and metrics:** only additions (`/api/stats`, `/plugins/files`,
  `POST /plugins/reload`, `/api/mcp/cache`, `/api/mcp/cache/clear`, new metrics).
- **Configuration:** every new key has a default; a 2.2 file loads (see the
  `analytics_node` exception above). Keys the proxy does
  not know are still warned and ignored (`strict_config = true` refuses them).

## Install or upgrade

```bash
# From crates.io (default features: pooling and Transaction Replay)
cargo install heliosdb-proxy --version 3.0.0 --locked

# With every module and the postgres/patroni topology providers
cargo install heliosdb-proxy --version 3.0.0 --locked --features "all-features,postgres-topology"

# Prebuilt binary (example: Linux x86_64), from this release's assets
curl -LO https://github.com/HeliosDatabase/HeliosDB-Proxy/releases/download/v3.0.0/heliosdb-proxy-linux-x86_64.tar.gz
curl -LO https://github.com/HeliosDatabase/HeliosDB-Proxy/releases/download/v3.0.0/heliosdb-proxy-linux-x86_64.tar.gz.sha256
sha256sum -c heliosdb-proxy-linux-x86_64.tar.gz.sha256
tar xzf heliosdb-proxy-linux-x86_64.tar.gz

# Docker
docker pull ghcr.io/heliosdatabase/hdb-heliosdb-proxy:3.0.0
```

Other assets: `heliosdb-proxy-linux-aarch64`, `heliosdb-proxy-macos-x86_64`,
`heliosdb-proxy-macos-aarch64`, each with a `.sha256` file. The prebuilt archives
contain the daemon only; `cargo install heliosdb-proxy` installs the `helios-plugin` CLI
next to it.

Upgrade a running proxy without dropping work: start the 3.0.0 binary on the same
addresses and send SIGUSR2 to the old process (see
[Signals](https://github.com/HeliosDatabase/HeliosDB-Proxy/blob/main/docs/configuration.md#signals)),
or stop it with SIGTERM and let it drain. Then check `GET /version`,
`GET /config` (`ignored_config_keys`) and, with plugins, `GET /plugins/files`.
